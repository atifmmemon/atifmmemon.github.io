Keynotes

  • Repurposing Automated Testing for ML Software Development and Deployment ML-powered features — and increasingly LLM-powered ones — behave non-deterministically and emerge from training rather than specification, so the classical assumption of a testable spec breaks down. Traditional testing during code development and metrics collected during model development fail to give an accurate view of user-level bugs, and online A/B metrics don't directly expose them either. The talk shows how large volumes of system test cases, mined for defect classes (partitions of the input space where ML-based software measurably underperforms), expose these bugs early and drive rapid improvement. 31 Mar–4 Apr 2025 · 18th IEEE International Conference on Software Testing, Verification and Validation (ICST 2025), Naples, Italy · researchr.org
  • MachineLearning × SoftwareTesting @ Apple Maps ML systems have two design characteristics — their ever-improving nature and learning-based emergent behavior — that create a moving target for functional regression testing. Unlike classical software, there is no fixed specification to test against, and expected outputs drift as the model learns from new data. The keynote presents a general methodology for automatically authoring and maintaining tests at planetary scale: using production data volume to refresh test inputs and expected outputs, data perturbation to achieve coverage adequacy, and clustering to triage failure patterns indicative of real bugs. May 2022 · 44th International Conference on Software Engineering (ICSE 2022) — SEIP Track · researchr.org
  • Acknowledging the Elephant in the Room: Brittle Test Cases Flaky tests — those that non-deterministically pass or fail under seemingly identical conditions — are a widespread but under-acknowledged problem in regression testing. The keynote names the elephant in the room and surveys the causes, consequences, and approaches for detecting and repairing flaky behavior. The topic has only grown in importance since: continuous-integration pipelines and ML-driven features amplify the cost of each flaky signal, and the techniques raised here foreshadow the flaky-test ranking and ML-based testing work that followed. 17 Apr 2012 · Regression 2012, Montreal

  • Which Test Oracle Should I Use for Effective GUI Testing? Test effectiveness and cost depend not just on the test cases but equally on the test oracle: the mechanism that decides whether an execution was correct. The talk compares 11 types of oracles across 660,000 test runs on four systems, showing that detailed oracle information with more complex procedures finds faults earlier and with fewer test cases, albeit at higher per-test cost. 22 May 2012 · 20th CREST Open Workshop “The Oracle Problem for Automated Software Testing”
  • Adaptive Test-Case Generation for Event-Driven Software Applications A fully automatic, feedback-driven technique for generating GUI test cases: a seed suite is run, the runtime effect of each event on all other events pinpoints “event-semantic interaction” relationships, and these drive the generation of new, more effective test cases. Studies on eight applications show that the feedback-based approach significantly outperforms baseline techniques and detects more faults than code-, event-, or interaction-coverage equivalents.
